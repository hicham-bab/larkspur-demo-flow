The story
THURSDAY, 07:40 · BOARD MEETS AT 09:00

"Which number do I say out loud?"

Larkspur Financial is a mid-size lender. Its Chief Risk Officer has two decks open, built by two teams from the same bank, the same loans and the same quarter.

Deck A · Risk team
Approval rate78.2%
Charge-off rate14.17%
Deck B · Finance
Approval rate65.3%
Charge-off rate14.59%

Nobody is lying. One team counted "Approve with Strict Conditions" as approved; the other divided losses by every loan, including loans that have not finished yet. The data sits in a Postgres core banking system: risk assessments, 40K loans, a 45K-contact marketing campaign, and 320 customer complaints nobody has modeled.

This is how Larkspur gets one answer by 09:00, and keeps it.

Keep it under 90 seconds. Every person in the room has lived the two-decks moment. The numbers are real results from this lab's data, and both "wrong" ones come back as bugs in Act 2.

Act 2 · Beat 1 The best moment of the act

A broken number that still looks plausible.

CHARGED OFF / ALL LOANS
14.17%

Includes loans that are still running and have no outcome yet. Every test passes.

CHARGED OFF / MATURED LOANS
14.59%

The governed definition. Only Fully Paid or Charged Off loans count.

Finance reports a charge-off rate of 14.59%, but the Semantic Layer metric charge_off_rate returns 14.17%. Nothing failed in the build. Find out which side is wrong and why, fix it, and add a test so this kind of definition drift fails the build next time.

Tests catch broken data. Only governed definitions catch a broken number.

Pause here. This is the bug that reaches a board deck in real life. Wizard should spot that the matured_loans description says "Fully Paid or Charged Off" while the metric counts every loan.

dbt Snowflake The handoff

dbt publishes the definitions as Snowflake semantic views.

-- models/06_semantic_views/sv_lending_book.sql
{{ config(materialized='semantic_view', schema='semantic') }}

tables (
  loans as {{ ref('fct_loans') }} primary key (loan_id)
)
metrics (
  loans.charge_off_rate as
    count_if(loans.is_charged_off)
    / nullif(count_if(loans.is_matured), 0)
    with synonyms = ('default rate')
)
  • SV_CREDIT_RISK: approval rate, high-risk exposure share, exposure by region and institution.
  • SV_LENDING_BOOK: charge-off and net loss rate by grade, purpose, state.
  • SV_TERM_DEPOSIT_CAMPAIGN: subscription rate by segment. Call duration left out on purpose (it leaks the outcome).

Built with Snowflake-Labs/dbt_semantic_view: in dbt lineage, built from contracted marts with ref(), rebuilt by the same prod job.

"The definitions now live in Snowflake. Over to you."
This is the seam between the two companies. The definitions are written once, in dbt, with tests; Snowflake serves them natively to Cortex Analyst, Cortex Code and Snowflake Intelligence.
